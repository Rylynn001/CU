# 画布长任务

助手将多次生成拆为最多 12 个步骤，先展示计划，再分别确认图片和视频参数。所有参数确认后，一次性保存节点、依赖连线和执行记录。每个图片步骤生成一张，视频步骤保留用户明确要求的时长。

例如“男主、女主 → 合影 → 8 秒视频”创建四个节点：角色图可并行，合影引用两张角色图的实际资产编号，视频引用合影。后台每三秒检查依赖，页面关闭或切换会话不会停止任务。

失败步骤会阻断其后续步骤。点击“重试失败步骤”只重做失败与被阻断的步骤，已成功的结果继续复用。网络/数据库暂时故障保留提交状态，用固定任务编号恢复；同一计划有数据库互斥锁，同一生成编号在 Redis 中原子去重。

## 提示词追问与续接

生成计划和提示词优化分工如下：

1. 意图节点决定是否生成，并拆出步骤和依赖。遇到“继续”“重试”或补充回答时，判断是否恢复服务端已有草稿；取消或换任务时不恢复。
2. 优化节点只改写当前步骤。`ready` 只返回最终 `prompt`；`needs_clarification` 只返回问题 `reply` 和缺失类型（创作内容或参考素材）。生成模型、比例等调用参数仍由面板选择。
3. 服务端检查字段互斥、空内容和明显的对话反问。角色台词中的问号不直接判错。不合格输出只纠正一次，仍不合格就保留草稿并提示重试，不调用生成工具。
4. 追问和错误暂停时，将完整原始计划、已优化步骤、当前步骤、问题和所选技能写入会话 `parameters.generation_draft`。用户补充后从暂停步骤继续；本轮补充的素材只加入当前步骤。
5. 所有提示词就绪后，才写入 `parameters.generation_request` 并展示参数面板。两个等待字段互斥，草稿不能被当成已确认任务提交。

代码阅读入口：`agents/graph/workflow.py` 管理暂停和恢复；`agents/graph/utils/prompt_validation.py` 负责输出校验；`api/workflow.py` 负责会话保存和参数确认。提示词校验是针对明显误返回的兜底，不是完整的自然语言语义审查。

## 启用

依次执行 `migrations/20261116_canvas_workflow.sql`、`migrations/20261117_generation_plans.sql`，已执行的迁移不要重复执行。然后重启后端；`main.py` 内置 worker 或独立 `worker.py` 都会启动计划调度。Redis 应保留现有队列和任务去重键。

## 验证

本次修复的后端回归：在 `background` 下运行 `python -m unittest test_prompt_generation -v`。测试隔离外部模型、数据库与生成服务，不消耗生成额度，覆盖五步计划暂停/重新加载/恢复、反问纠正、失败重试、取消换任务和参考素材续接。

前端：在 `comfy-web` 下运行 `node --test tests/workflowChat.test.mjs tests/canvasGraph.test.mjs` 和 `npm run check`。

当前复用现有供应商 worker，不自动重新发送已经进入供应商处理阶段的任务。若 worker 在供应商处理中被强制结束，应先核对生成历史和供应商结果，避免重复扣费；计划调度会继续推进数据库已经记录完成的步骤。
