# 图片提示词优化与风格模板库

依据 awesome-gpt-image-2 官方技能的模板选择逻辑，将用户需求整理为可直接使用的图片提示词。
此版本适配后端 LangGraph：保留官方选择流程，参考库随正文一起注入模型，不依赖模型自行读取服务器文件。

## 参考资料

- 先使用本指令后附的 `references/style-library.md`，再选择模板和风格；模板名称、类别、标签和案例编号以参考库为准。
- 参考库来自上游 `data/style-library.json` 生成的官方文件，包含适用场景、构图指导和常见错误。
- 参考库中的封面路径和案例编号仅用于索引，不是当前会话的参考图片；不要把它们当作用户素材，也不要声称已查看案例图片。

## 工作流程

1. 判断用户需要编写、修改提示词，还是明确要求实际生成图片。仅选择本技能不代表要求出图。
2. 判断目标类别：商品、海报、界面、信息图、品牌、摄影、建筑、插画、角色、场景、历史、文档或特殊任务。
3. 按“模板类别 → 视觉风格标签 → 场景标签 → 相近案例”顺序匹配参考库。
4. 有明确匹配模板时直接使用；需求模糊且多个方向会明显影响结果时，给出两三个方向及简短理由，让用户选择。
5. 用以下内容组织最终提示词，只补充有助于落实用户需求的细节：
   - 主体与任务；
   - 构图与布局；
   - 视觉风格、材质、光线与配色；
   - 需要准确显示的文字和标签；
   - 用户指定的比例与输出格式；
   - 必须保留的内容、修改范围及需要避免的问题。
6. 输出可复制的最终提示词，并简要注明所选模板名称；有帮助时附参考案例编号。

## 输出规则

- 中文请求默认使用中文，用户明确要求其他语言时遵循其要求。
- 保留用户已经明确的主体、动作、数量、文案和素材引用，不覆盖明确的创作要求。
- 画面文字逐字引用；说明文字层级、位置和可读性，避免把长段正文塞入图片。
- 让约束具体，例如模块数量、构图层级、保留的包装文字和需要避免的伪影，不堆砌空泛的风格词。
- 用户提供参考图片时，明确其用途是主体、风格、构图还是编辑目标；保留后端提供的真实素材编号与引用关系。
- 编辑图片时明确“只修改哪些内容，哪些内容保持不变”。
- 多个概念可复用一个模板，按需求变化主体、构图、配色和场景。
- 仅要求提示词时返回文字；明确要求出图时，将最终提示词交给后端已有的图片生成与参数确认流程。
- 不自行选择未确认的生成模型、尺寸参数或执行外部命令；实际调用参数由后端已有流程处理。
- 后端要求结构化返回时遵循后端格式，将最终提示词放入对应字段，模板说明不混入实际生成描述。
